# AI-buddy — помощник стажёра в Slack

Hack&Change 2026, кейс Авито. AI-buddy — личный чат в имитации Slack. Стажёр E1 просит стартовую задачу. Бэкенд отбирает в тестовой Jira только допустимые задачи, модель выбирает одну и объясняет выбор. Бэкенд назначает задачу и сам отправляет отчёт руководителю. На частые вопросы стажёра (1:1, график, отгул, доступы, код-ревью и другие) бот отвечает сам из базы ответов руководителя, не отвлекая его.

Все профили, задачи, каналы и инструкции синтетические. Jira и Slack — локальные имитации на PostgreSQL.

## Состав

| Папка | Что внутри |
| --- | --- |
| `backend/` | Go 1.25: HTTP API, правила допуска, адаптер Jira на PostgreSQL, клиент OpenRouter, тесты |
| `frontend/` | React 19 + TypeScript: интерфейс Slack, TanStack Query, Zod, тесты Vitest |
| `openspec/` | Спецификация поведения: `starter-pick-go`, `task-progress`, `first-step-and-blockers`, `faq-answers` |
| `Demo/` | Эталонный прототип на Python и SQLite. Новый стек повторяет его поведение |
| `docker-compose.yml` | PostgreSQL, API и веб-интерфейс |

## Запуск через Docker

Нужен Docker Desktop.

```bash
docker compose up --build
```

Откройте http://localhost:3000. Для чистого прогона удалите данные: `docker compose down -v`.

## Запуск без Docker

Нужны Go 1.25+ и Node 22+. Если `DATABASE_URL` не задан, API сам поднимает локальную PostgreSQL 17. При первом запуске он скачивает её бинарные файлы (около 22 МБ). Данные хранятся в папке кэша пользователя: на Windows это `%LOCALAPPDATA%\ai-buddy\pg`.

```bash
cd frontend && npm ci && npm run build
cd ../backend && go run ./cmd/api
```

Откройте http://127.0.0.1:8080. API раздаёт собранный интерфейс из `frontend/dist`.

Для чистой базы укажите новую папку в `LOCAL_PG_DIR`, а при занятом порте — другой `LOCAL_PG_PORT` (по умолчанию 54329). Для своей PostgreSQL задайте `DATABASE_URL`. Режим разработки интерфейса с горячей перезагрузкой: `npm run dev` в `frontend/`, запросы `/api` уходят на `127.0.0.1:8080`.

### Режим без модели: какие фразы понимают правила

Без `LLM_API_KEY` намерение определяют правила по ключевым словам (`backend/internal/domain`). Регистр не важен, проверка идёт по началу слова.

| Что пишет стажёр | Как понимают правила | Примеры |
| --- | --- | --- |
| Глагол просьбы + слово о задаче | Подбор задачи. Если задача уже есть — напоминание о ней | «Подбери мне стартовую задачу», «Дай задание», «Хочу тикет», «Нужна задача». Глаголы: подбер-, подбир-, выбер-, выбир-, найд-, назнач-, дай, дайте, предлож-, нуж-, хочу. Слова: задач-, задан-, тикет |
| «Что (мне) (можно) взять в работу» | Подбор задачи | «Что можно взять в работу?» |
| Слова о препятствии, если есть задача | Блокер: бот уточняет, что мешает | «Не могу…», «не получается», «не выходит», «не запускается», «не работает», «не открывается», «застрял(а)», «ошибка», «падает», «нет доступа», «блокер» |
| Тема из базы частых вопросов (проверяется после подбора и блокера) | Ответ из базы без участия руководителя | «Когда встреча с моим руководителем?», «во сколько дейлик», «можно отпроситься в пятницу?», «как оформить пул реквест», «можно поработать удалённо?». Ключевые слова каждого вопроса — поле `match` в разделе `faq` файла `demo_data.json` |
| Вопрос о статусе или сроке, если есть задача | Статус, срок и кнопка перехода, статус не меняется | «статус», «перевести», «ревью», «в работу», «срок», «дедлайн» |
| Любой другой вопрос, если есть задача | Первый шаг и шаги инструкции | «С чего начать?», «Где посмотреть эту метрику?» |
| Всё остальное без задачи | Предложение подобрать задачу и список тем частых вопросов | «Привет», «Есть что-нибудь для меня на сегодня?», «Да» |

Частые вопросы правила узнают в свободной формулировке:
- регистр, «ё», знаки препинания, дефисы и пробелы внутри фразы не важны: «пул-реквест», «пул реквест» и «пулреквест» — одно и то же;
- ключ — начало слова, поэтому подходят другие окончания: «отгул», «отгула», «отгулы»;
- в словах от 5 букв допускается опечатка (от 9 букв — две): «пул рекуест», «документацыя»;
- части ключа через `+` ищутся в любом месте сообщения: `встреч+руковод` находит «встреча с моим руководителем»;
- ключи до 3 букв («pr», «мр», «1:1») сравниваются с целым словом, чтобы «пр» не находилось в «привет».

Если сообщение не подошло ни к одному правилу, бот перечисляет темы частых вопросов. С ключом OpenRouter вопрос по смыслу выбирает модель, и формулировка может быть любой.

Ответ на уточнение блокера правила сверяют с пунктами инструкции задачи:
- **Нужен наставник:** BACK-112 — «доступ», «403», «прав», «не пускает», «стенд недоступ»; BACK-118 — «доступ», «403», «прав», «репозитори». Сюда же относятся явные просьбы: «наставник», «без помощи», «нужна помощь», «помоги», «сам(а) не», «не справлюсь».
- **Решается по инструкции:** BACK-112 — «флаг», «кэш не», «набор», «запрос», «filters-smoke»; BACK-118 — «make», «не запуска», «падает», «ошибк».
- **Не совпало ни с чем** — блокер уходит наставнику с общей просьбой разобраться.

Свободные формулировки вроде «Есть что-нибудь для меня на сегодня?» и короткое «Да» после предложения правила не распознают — для них нужна модель. Для показа без ключа используйте кнопку-подсказку «Подбери мне стартовую задачу».

### Проверка с OpenRouter (14.11.2026)

Основной сценарий пройден с реальной моделью дважды: на `nvidia/nemotron-3.5-super-vl:free` и на `inclusionai/ling-3.2-flash:free`. В обоих прогонах модель:
- распознала «Есть что-нибудь для меня на сегодня?» и «Да» после приветствия как просьбу о задаче, а приветствие — нет;
- выбрала задачу только из разрешённых кандидатов и объяснила выбор;
- ответила на «С чего начать?» и «Где посмотреть эту метрику?» по тестовой инструкции, без выдуманных ссылок;
- на «Как перевести задачу в работу?» объяснила кнопку, а статус не изменился;
- оценила блокер «нужен доступ к тестовому стенду» как требующий наставника, и наставник получил одно сообщение.

Отказы по правам и по занятости, повтор блокера и уточняющий вопрос обрабатываются без модели (режим ответа `system`).
| Модель | Один вызов модели | Шаг с подбором (два вызова) | Замечания |
| --- | --- | --- | --- |
| `nvidia/nemotron-3.5-super-vl:free` | 2–10 с | ≈ 6 с | Использовала Markdown; теперь его просим не использовать, а `**` убирает сервер |
| `inclusionai/ling-3.2-flash:free` | 15–22 с | ≈ 36–42 с | Медленнее, встречаются опечатки |
| `thinkingmachines/inkling-2-small:free` | — | — | Недоступна: «not available in your region», к тому же не поддерживает `tool_choice` |

Ограничения бесплатного тарифа OpenRouter:
- 50 запросов к бесплатным моделям в день на аккаунт. Полный прогон демо — около 13 вызовов, то есть 3–4 прогона в день. После этого OpenRouter отвечает `429 free-models-per-day`, и список запасных моделей не помогает. Пополнение на 10 кредитов поднимает лимит до 1000 запросов в день.
- Отдельные бесплатные модели бывают временно перегружены у провайдера. На этот случай `LLM_MODEL` принимает список моделей.
- Для защиты: держите готовым режим без ключа и прогоните сценарий с ключом заранее в тот же день.

Ошибки модели показываются стажёру по-разному, в базе ничего не сохраняется, повтор работает:
- неверный ключ (`401/402/403`) — «OpenRouter не принял ключ»;
- лимит (`429`) — «перегружена запросами, подождите минуту»;
- тайм-аут 90 с на вызов модели — «не ответила вовремя»;
- любой другой сбой — «повторите сообщение».

Причина каждой ошибки пишется в лог сервера (`external service failed`).

## Путь демо

На чистой базе в детерминированном режиме:

1. **Елена:** «Подбери мне стартовую задачу». Бот назначает BACK-112 «Проверить кэширование фильтров поиска», объясняет пользу и называет первый шаг. Над чатом появляется статус «Назначена».
2. **Елена:** «С чего начать?» Бот отвечает по текущей задаче. Новое назначение и отчёт не создаются.
3. **Алексей:** «Что можно взять в работу?» Бот назначает BACK-118.
4. **Илья:** просит задачу. Бот отвечает, что подходящие задачи уже взяли другие стажёры. Нехватку прав он не упоминает.
5. **Дарья:** просит задачу. Бот отвечает, что для её грейда и допусков стартовых задач нет. BACK-112 и BACK-118 модели не передаются.
6. **Мария:** в личных сообщениях четыре отчёта. В каждом ФИО, грейд, команда и итог. При назначении добавлены причина выбора и факты, проверенные бэкендом: команда, грейд, метка, классификация и допуски.

С OpenRouter свободные формулировки вроде «Есть что-нибудь для меня на сегодня?» распознаёт модель. Порядок BACK-112 и BACK-118 может отличаться. Какие фразы понимает режим без модели, описано в разделе «Режим без модели».

Кнопки:
- «Сбросить чат» у стажёра очищает переписку и сохраняет назначение.
- «Начать подбор заново» снимает назначение этого стажёра, очищает его чат и удаляет его отчёты.
- «Сбросить чат» у руководителя скрывает полученные отчёты, новые продолжают приходить.

### Статусы, сроки и напоминания

7. **Елена:** над чатом панель задачи: статус, срок, сколько осталось, следующий шаг и кнопка. Срок — день назначения плюс `due_days` задачи (BACK-112 — 3 дня, BACK-118 — 4).
8. **Елена:** «Как перевести задачу в работу?» Бот объясняет статус, срок и кнопку. Статус не меняется.
9. **Елена:** «Взять в работу». Бэкенд проверяет, что задача её и переход допустим, записывает статус в имитацию Jira, бот подтверждает «В работе» и даёт следующий шаг. Затем «Отправить на ревью».
10. **Полоса «Демо-время»:** «Следующий день» сдвигает дату для всех профилей. Накануне срока стажёр получает напоминание, после срока — сообщение о просрочке. Каждое приходит один раз.
11. **Мария:** блок «Задачи стажёров» показывает статус и срок каждого стажёра и подсвечивает просрочку.

Правила:
- Переходы только вперёд: «Назначена» → «В работе» → «На ревью». Повторное подтверждение ничего не меняет. Переход назад или через шаг — `409`, чужая задача или руководитель — `403`, сбой записи в Jira — `503` без подтверждения в чате.
- Часовой пояс демо — Москва (UTC+3). Демо-время — общий сдвиг в днях в PostgreSQL. «Сбросить время» возвращает сегодняшнюю дату.
- Напоминания создаёт планировщик в Go: при старте, каждые 30 секунд и сразу после сдвига времени. Поэтому они появляются, даже если чат закрыт, и видны при следующем открытии. Каждое напоминание имеет ключ «стажёр + вид + задача + срок»: повторная проверка, перезапуск и переключение профиля не создают дублей.
- На ревью напоминаний нет. Если срок перенесли, проверяется новый срок. Если назначение сняли или доступ к задаче пропал, напоминаний нет. Пропущенное «накануне» после срока не отправляется, приходит только просрочка.
- «Сбросить чат» скрывает подтверждения и напоминания без повторной отправки. «Начать подбор заново» удаляет их вместе с назначением.

### Первый шаг и блокер

12. **Елена:** «С чего начать?» Бот отвечает по тестовой инструкции Confluence для BACK-112: дашборд Grafana и панель «p95 latency, ms», один набор запросов `filters-smoke-200` для замеров без кэша и с кэшем, куда приложить результат в Jira. В панели задачи — ссылки на инструкцию, дашборд и стенд. Каждая открывает страницу `/demo/<id>` с баннером «Тестовый ресурс». Для BACK-118 бот называет тестовый репозиторий Bitbucket, каталог `tests/filters/` и фикстуру.
13. **Елена:** «Не могу запустить второй замер». Бот уточняет, что мешает, и предлагает проверку из инструкции. Наставник пока ничего не получает.
14. **Елена:** «Для второго замера нужен доступ к тестовому стенду, сама не справлюсь». Бот фиксирует блокер и пишет наставнику. Над чатом появляется «Блокер у наставника» с кнопкой «Блокер снят».
15. **Олег (наставник):** в личных сообщениях «Запросы о помощи»: стажёр, задача, статус, срок, препятствие и конкретная просьба. Кнопка «Помог, снять блокер» закрывает запрос, Елена получает подтверждение в чате.

Правила:
- Если уточнение совпадает с пунктом инструкции, который стажёр решает сам (например, «флаг кэша не включается»), бот даёт шаг и наставника не зовёт.
- Вопросы о задаче и метрике наставнику не уходят. Повтор при открытом блокере не создаёт второе сообщение: в PostgreSQL есть уникальный индекс на активный блокер стажёра по задаче.
- Запрос о помощи получает наставник из профиля стажёра, а если наставника нет — руководитель.
- Если инструкции нет или у стажёра нет к ней допуска, бот прямо говорит об этом, не придумывает ссылки и предлагает спросить наставника. Страницы ресурсов проверяют допуск на сервере (`403` без допуска, `401` без сессии).
- «Начать подбор заново» удаляет блокеры прежнего назначения.

### Частые вопросы

16. **Дарья:** «Когда у меня 1:1 с руководителем?» Бот отвечает текстом из базы частых вопросов, ответ помечен «Из базы частых вопросов». Задача для этого не нужна.
17. **Елена:** «Как взять отгул?», затем «Как оформить pull request на код-ревью?» Оба ответа из базы. Назначение и статус задачи не меняются.
18. **Мария:** новых сообщений нет — на частые вопросы бот ответил сам.

Правила:
- 12 вопросов стажёра к руководителю хранятся в таблице `faq` PostgreSQL: 1:1, цели, доступы, стендап, рабочий график, болезнь, отгул, pull request, документация, к кому идти с вопросом, оценка стажировки, удалённая работа. Источник — раздел `faq` в `backend/internal/seed/demo_data.json`, при старте записи добавляются или обновляются по `id`. Ответы — тестовые данные: перед пилотом руководитель заменяет их правилами своей команды.
- Бот отдаёт ответ из базы дословно. Модель только выбирает подходящий вопрос — в том же вызове, что и намерение (поле `faq_id`), поэтому лишнего запроса к OpenRouter нет. Тексты ответов в модель не уходят. Стажёр получает только вопросы своей команды.
- Сообщение о препятствии остаётся блокером, а вопрос о статусе своей задачи — вопросом по задаче, даже если тема похожа: «Нет доступа к стенду» уходит в блокер, «Как отправить задачу на ревью?» — в ответ о статусе.
- Если модель решила, что это общий вопрос о работе, но в базе ответа нет, бот прямо говорит об этом и советует спросить руководителя или наставника. Руководителю автоматически ничего не уходит.

```
                                              ├─ kb_docs         имитация Confluence, Grafana, Bitbucket
                                              ├─ blockers        блокеры и запросы наставнику
                                              ├─ faq             частые вопросы и ответы руководителя
                                              └─ lead_inbox      отчёты руководителю
           планировщик напоминаний (горутина, 30 с) ──▶ buddy.RunReminders
```

- **Права.** Роль, команда, грейд, допуски и руководитель берутся из справочника в PostgreSQL, а не из текста сообщения. Задача проходит, только если она открыта, не назначена, имеет метку `starter`, относится к команде стажёра, подходит по грейду и допускам и явно классифицирована как `internal`. Остальные задачи отсекаются до вызова модели.
- **Модель.** Модель возвращает намерение (`pick_task`, `task_question`, `blocker`, `faq`, `other`), ID частого вопроса, ID задачи и оценку блокера (`needs_human`, `self_step`, `request`) через принудительный вызов функции. Сервер проверяет структуру ответа и допустимые значения. ID должен быть из списка кандидатов. ФИО стажёра в модель не уходит. Ссылки модель берёт только из инструкции, к которой у стажёра есть допуск. Без ключа те же решения принимают правила по ключевым словам.
- **Запись.** Запрос к модели идёт вне транзакции. Затем в одной транзакции сервер заново сверяет версию чата, историю, назначение и доступность задачи. После этого он записывает назначение, реплику и отчёт. Ограничения PostgreSQL не дают назначить одну задачу двум стажёрам или выдать стажёру вторую. Повтор с тем же `request_id` возвращает сохранённый результат.
- **Ошибки.** Сбой модели — `502`, сбой Jira или базы — `503`. В обоих случаях ничего не сохраняется, повтор работает. «Задачи заняты» и «нет задач по правам» — нормальные ответы бота с разным текстом.
- **Настоящая Jira.** Сейчас адаптер Jira читает и пишет таблицы `jira_tickets` и `jira_assignments`. При подключении настоящей Jira источником статуса и назначения станет она. Правила допуска останутся в Go, а Slack и корпоративная авторизация заменят демосессии.

Поведение и API описаны в спецификациях: [подбор](openspec/changes/starter-pick-go/specs/starter-pick/spec.md), [статусы и сроки](openspec/changes/task-progress/specs/task-progress/spec.md), [первый шаг и блокеры](openspec/changes/first-step-and-blockers/specs/first-step-and-blockers/spec.md), [частые вопросы](openspec/changes/faq-answers/specs/faq-answers/spec.md).

## Как измерить эффект

Гипотеза команды: в первые 2–3 недели рутина концентрируется вокруг одних и тех же вопросов — какую задачу взять, где инструменты, что делать дальше, кто застрял. AI-buddy должен сократить время стажёра до первого самостоятельного шага, число обращений к наставнику и время руководителя на сбор статусов. **Ниже — метод замера. Измеренных результатов пока нет:** демо работает на синтетических данных.

| Метрика | Как считаем | Откуда данные |
| --- | --- | --- |
| Время до первого самостоятельного шага | От назначения задачи до подтверждённого перехода «В работе». Отдельно — до «На ревью» | `jira_assignments.created_at`, подтверждения статуса в `bot_events` |
| Обращения к наставнику | Число блокеров, дошедших до наставника, и доля проблем, решённых по инструкции без него | `blockers`: `opened_at` заполнен — к наставнику, `status = self_help` — сам |
| Вопросы к боту вместо наставника | Сообщения стажёра боту после назначения. Ответы из базы частых вопросов — реплики с `mode = 'faq'`: эти вопросы не дошли до руководителя | `chat_turns` (после «Сбросить чат» история удаляется, поэтому для замера чат не сбрасывать) |
| Время руководителя на сбор статусов | Минуты в неделю на вопросы «как дела с задачей» — до и после блока «Задачи стажёров» | Опрос руководителей или трекинг времени: в базе этих данных нет |

Цифры по текущей базе печатает команда, которая работает и с базой, поднятой API без Docker:

```bash
cd backend && go run ./cmd/metrics
```

Пример вывода с демобазы (реальная модель, 14.11.2026):

```
Стажёр                 Задача    До «В работе»  До «На ревью»  Вопросов боту  Блокеров к наставнику  Решено по инструкции
Алексей Сергеевич Ким  BACK-118  —              —              1              0                      0
Елена Игоревна Орлова  BACK-112  —              —              7              1                      0
```

С чем сравнивать в пилоте:
- **База** — предыдущий поток стажёров без AI-buddy. Время до первого шага берём из истории Jira (назначение → «В работе»), обращения к наставнику — из личных сообщений или опроса наставников, время на статусы — из опроса руководителей.
- **Пилот** — половина нового потока с AI-buddy, половина без него, первые 2–3 недели, та же команда и тот же тип стартовых задач.
- **Успех** — медианное время до «В работе» и число обращений к наставнику ниже, чем в базе, при той же доле задач, дошедших до ревью.
