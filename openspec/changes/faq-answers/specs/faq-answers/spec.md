# Частые вопросы стажёра

Вопросы и ответы — синтетические тестовые данные.

## ADDED Requirements

### Requirement: База частых вопросов

Система SHALL хранить в PostgreSQL не меньше 10 частых вопросов стажёра к руководителю. У каждой записи есть `id`, команда, короткая тема, текст вопроса, утверждённый ответ и ключевые слова для режима без модели. Источник ответа — таблица `faq`: изменённый в ней текст бот выдаёт со следующего сообщения.

#### Scenario: Загрузка при старте

- **WHEN** сервер запускается на чистой или существующей базе
- **THEN** записи из `demo_data.json` (раздел `faq`) добавляются или обновляются по `id`

#### Scenario: Только своя команда

- **WHEN** стажёр пишет боту
- **THEN** сервер передаёт в распознавание только вопросы команды стажёра из его профиля в PostgreSQL

### Requirement: Ответ из базы

Система SHALL отвечать на вопрос из базы утверждённым текстом без участия руководителя.

#### Scenario: Вопрос есть в базе

- **WHEN** стажёр, с задачей или без неё, спрашивает, например, «Когда у меня 1:1 с руководителем?» или «Как взять отгул?»
- **THEN** бот отвечает текстом из `faq` и добавляет пометку «Ответ из базы частых вопросов команды (тестовые данные)»
- **AND** реплика сохраняется с режимом `faq`, в интерфейсе она помечена «Из базы частых вопросов»
- **AND** руководитель не получает отчёт, наставник не получает запрос, назначение и статус задачи не меняются

#### Scenario: Ответа в базе нет

- **WHEN** модель определила общий вопрос о работе в команде, но ни одна запись не подходит
- **THEN** бот говорит, что в базе частых вопросов ответа нет, и советует спросить руководителя или наставника
- **AND** автоматически руководителю ничего не отправляется

#### Scenario: Другие намерения важнее

- **WHEN** стажёр с задачей пишет о препятствии («Не могу запустить второй замер», «Нет доступа к стенду»)
- **THEN** это блокер, а не вопрос из базы
- **WHEN** стажёр спрашивает о статусе или сроке своей задачи («Как отправить задачу на ревью?»)
- **THEN** бот отвечает по задаче, а не из базы
- **WHEN** стажёр просит подобрать задачу
- **THEN** идёт подбор

#### Scenario: Свободная формулировка без модели

- **WHEN** стажёр пишет вопрос своими словами: «как оформить пул реквест», «пулреквест», «пул рекуест», «когда встреча с моим руководителем», «можно поработать удалённо?»
- **THEN** правила находят вопрос из базы: регистр, «ё», знаки, дефисы и пробелы внутри фразы не важны, слово узнаётся по началу (другие окончания), в словах от 5 букв допускается опечатка, части ключа через «+» ищутся в любом месте сообщения
- **AND** вопросы о задаче («На каких стендах делать замер?», «Как перевести задачу в работу?») не принимаются за частый вопрос

#### Scenario: Бот не понял

- **WHEN** сообщение не похоже ни на одно действие и ни на вопрос из базы
- **THEN** ответ бота перечисляет темы частых вопросов команды из поля `topic`, чтобы стажёр знал, о чём можно спросить

#### Scenario: Повтор запроса

- **WHEN** приходит повтор с тем же `request_id`
- **THEN** реплика не дублируется

### Requirement: Модель в распознавании частых вопросов

С ключом OpenRouter функция `classify_request` SHALL возвращать намерение `faq` и поле `faq_id` из списка `[id…, "none"]` за один вызов модели. В модель уходят только `id` и тексты вопросов, ответы не уходят. Сервер проверяет, что `faq_id` есть в списке, иначе ответ модели отклоняется (`502`, ничего не сохраняется). Если намерение не `faq`, `faq_id` не используется. Без ключа те же решения принимают правила: подбор задачи → блокер (при наличии задачи) → совпадение с ключевыми словами записи → вопрос по задаче → прочее.
