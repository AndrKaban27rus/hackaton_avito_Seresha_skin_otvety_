# Перенос подбора стартовой задачи на Go, PostgreSQL и React

## Зачем

Рабочий сценарий подбора есть только в эталоне `Demo/` (Python, SQLite, HTML/JS). Кейс оценивает совместимость со стеком Авито, поэтому переносим тот же путь на Go, PostgreSQL и React/TypeScript без потери проверок прав, повторов и гонок.

## Что меняется

- Go-приложение `backend/` с модулями: правила допуска (`domain`), адаптер Jira и хранилище демо (`store`, PostgreSQL), порт модели (`llm`: детерминированный режим и OpenRouter), сценарий чата (`buddy`), HTTP API (`httpapi`).
- React/TypeScript-интерфейс `frontend/` в виде локального Slack: выбор демопрофиля, личный чат с AI-buddy, отчёты руководителю.
- Docker Compose из трёх сервисов: `postgres`, `api`, `web`. Без Docker API поднимает встроенный PostgreSQL.
- Сессии демопрофилей хранятся в PostgreSQL и переживают перезапуск.
- Отказ в подборе различает причины: все допустимые задачи заняты, нет задач для профиля, сбой Jira, сбой модели.
- Добавлен тестовый профиль без допуска `search_dev`.

## Вне этого изменения

Статусы «В работе» и «На ревью», сроки и напоминания, ссылки на инструменты и инструкции, блокеры и сообщения наставнику. Они пойдут следующими изменениями поверх этого API.

## Источник состояния

В демо адаптер Jira читает задачи и пишет назначения в таблицы PostgreSQL `jira_tickets` и `jira_assignments`. При подключении настоящей Jira источником статуса и назначения станет Jira, а правила допуска останутся в Go.
