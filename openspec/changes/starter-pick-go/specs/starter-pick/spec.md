# Подбор стартовой задачи

Все профили, задачи, каналы и ответы тестовые. Jira и Slack — локальные имитации на PostgreSQL.

## ADDED Requirements

### Requirement: Демопрофиль и сессия

Система SHALL выдавать сессию только для профиля из тестового справочника. Роль, команда, грейд, допуски и руководитель берутся из справочника в PostgreSQL. Текст сообщения и вывод модели не меняют права.

#### Scenario: Выбор профиля

- **WHEN** клиент отправляет `POST /api/session` с `{"profile": "<id>"}`
- **THEN** сервер создаёт сессию в PostgreSQL, ставит куку `demo_session` (HttpOnly, SameSite=Strict) и возвращает состояние профиля
- **AND** прежняя сессия этого браузера удаляется

#### Scenario: Запрос без сессии или с чужого источника

- **WHEN** запрос к `/api/state` или к действию приходит без действующей сессии
- **THEN** сервер отвечает `401` и не меняет состояние
- **WHEN** `POST` приходит с заголовком `Origin`, который не совпадает с `Host`
- **THEN** сервер отвечает `403`

#### Scenario: Перезапуск сервера

- **WHEN** сервер перезапускается на той же базе
- **THEN** сессии, назначения, переписка и отчёты восстанавливаются

### Requirement: Безопасный выбор задачи

Система SHALL рассматривать только открытые неназначенные задачи с меткой `starter` своей команды, с грейдом стажёра в списке `grades`, со всеми нужными допусками из `requires` и с явной классификацией `internal`. Непрошедшие задачи исключаются до вызова модели и не попадают в ответы и отчёты.

#### Scenario: Стажёр просит стартовую задачу

- **WHEN** стажёр пишет в личный чат просьбу в свободной формулировке, например «Есть что-нибудь для меня на сегодня?»
- **THEN** модель (или правила в детерминированном режиме) определяет намерение `pick_task`, `task_question` или `other`
- **AND** при `pick_task` без назначения сервер ищет кандидатов и передаёт модели только их ID, названия и описания
- **AND** сервер проверяет, что выбранный ID есть среди кандидатов, и повторно сверяет доступ и свободу задачи в транзакции записи
- **AND** стажёр получает ID, название, обоснование и первый шаг после записи в имитацию Jira

#### Scenario: Детерминированный режим

- **WHEN** `LLM_API_KEY` не задан
- **THEN** намерение распознаётся правилами, задача выбирается по наибольшему `okr_priority`, ответы помечены как тестовые
- **AND** на чистой базе первый стажёр получает BACK-112, второй — BACK-118, третий — сообщение «задачи заняты»

#### Scenario: Все допустимые задачи заняты

- **WHEN** у стажёра есть права на стартовые задачи, но все они назначены другим
- **THEN** стажёр получает сообщение, что подходящие задачи уже взяли, без упоминания нехватки прав
- **AND** руководитель получает отчёт с причиной «задачи заняты»

#### Scenario: Нет задач для профиля

- **WHEN** ни одна задача не проходит проверку грейда, команды, допусков и классификации, даже без учёта назначений
- **THEN** стажёр получает сообщение, что для его грейда и допусков стартовых задач нет
- **AND** руководитель получает отчёт с этой причиной без деталей исключённых задач

#### Scenario: Одновременные запросы

- **WHEN** два стажёра почти одновременно получают одну и ту же задачу от модели
- **THEN** назначение получает только один, второй получает `409` с предложением повторить подбор
- **AND** ограничения PostgreSQL не допускают двух назначений одной задачи и двух назначений одного стажёра

### Requirement: Ошибки внешних сервисов

Система SHALL отличать ошибки модели и хранилища от бизнес-результата и не сохранять частичный результат.

#### Scenario: Сбой модели

- **WHEN** OpenRouter недоступен, отвечает ошибкой, не укладывается в тайм-аут, возвращает неизвестное намерение, ID вне списка кандидатов или некорректную структуру
- **THEN** сервер отвечает `502` с предложением повторить сообщение
- **AND** назначение, реплика и отчёт не создаются

#### Scenario: Слово на другом языке в ответе модели

- **WHEN** в тексте, который пишет модель (обоснование, первый шаг, ответ по задаче, оценка блокера), есть латинское слово из трёх и более букв, которого нет во входных данных модели и в списке названий инструментов («serviert»)
- **THEN** сервер один раз повторяет запрос к модели и записывает в лог найденные слова
- **AND** если и второй ответ содержит такие слова, стажёр получает его, а в логе остаётся предупреждение: ответ лучше ошибки

#### Scenario: Сбой Jira или базы

- **WHEN** запись в имитацию Jira или чтение состояния завершается ошибкой
- **THEN** сервер отвечает `503` «Тестовый сервис временно недоступен. Повторите запрос.»
- **AND** назначение, реплика и отчёт не создаются, повтор после восстановления работает

### Requirement: Отчёт руководителю

Назначение, реплика стажёра и отчёт руководителю SHALL сохраняться одной транзакцией. Отчёт адресуется руководителю из профиля стажёра и содержит ФИО, роль, грейд, команду и результат.

#### Scenario: Повтор подбора

- **WHEN** стажёр повторяет запрос с тем же `request_id` или просит задачу при уже назначенной
- **THEN** в Jira остаётся одно назначение, руководитель получает не больше одного отчёта на каждый исход
- **AND** повтор `request_id` с другим текстом отклоняется с `409`

### Requirement: Переписка о задаче

Система SHALL сохранять историю личного чата и давать модели контекст текущей задачи и до восьми последних пар реплик.

#### Scenario: Уточнение

- **WHEN** стажёр с назначением спрашивает «С чего начать?»
- **THEN** бот отвечает по текущей задаче и истории, не создавая назначение или отчёт

#### Scenario: Сброс чата стажёра

- **WHEN** стажёр нажимает «Сбросить чат»
- **THEN** история очищается, назначение остаётся, следующий вопрос обрабатывается с текущей задачей и пустой историей
- **AND** ответ на запрос, начатый до сброса, отклоняется с `409` и не восстанавливает историю

#### Scenario: Стажёр повторяет демо подбора

- **WHEN** стажёр нажимает «Начать подбор заново»
- **THEN** система очищает его переписку, снимает его тестовое назначение и удаляет его отчёты о подборе
- **AND** назначения других стажёров не меняются

#### Scenario: Руководитель очищает чат с отчётами

- **WHEN** руководитель нажимает «Сбросить чат»
- **THEN** полученные отчёты скрываются, в том числе после перезагрузки, а новые продолжают поступать
- **AND** руководитель не может отправлять сообщения боту и сбрасывать подбор (`403`)

## API

| Метод и путь | Вход | Результат |
| --- | --- | --- |
| `POST /api/session` | `{"profile"}` | Состояние, кука сессии |
| `GET /api/state` | — | Состояние профиля |
| `POST /api/chat` | `{"message", "request_id"}` (1–1200 символов, ID `[A-Za-z0-9_-]{1,80}`) | Состояние |
| `POST /api/chat/reset` | `{}` | Состояние |
| `POST /api/pick/reset` | `{}` | Состояние (только стажёр) |
| `GET /healthz` | — | `{"status":"ok"}` |

Ошибки возвращаются как `{"error": "<текст для пользователя>"}` с кодами `400`, `401`, `403`, `404`, `409`, `415`, `502`, `503`.
