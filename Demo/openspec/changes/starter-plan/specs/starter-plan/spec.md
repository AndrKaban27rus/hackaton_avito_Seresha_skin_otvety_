# Подбор задачи в Slack

## ADDED Requirements

### Requirement: Безопасный выбор задачи

Система SHALL выбирать из открытых неназначенных стартовых задач команды с явной классификацией internal. Грейд и допуски берутся из тестового профиля стажёра.

#### Scenario: Стажёр просит стартовую задачу

- **WHEN** стажёр просит бота подобрать задачу в личном чате в свободной формулировке
- **THEN** модель определяет намерение по сообщению и контексту диалога, а сервер начинает поиск по профилю стажёра при намерении подбора
- **AND** модель получает для выбора только задачи, прошедшие проверку
- **AND** сервер проверяет предложенный ID по исходному списку и повторно сверяет доступ перед назначением
- **AND** стажёр получает ID, название и первый шаг после записи в имитацию Jira

#### Scenario: Список кандидатов пуст

- **WHEN** открытых допустимых задач нет
- **THEN** стажёр получает сообщение об отсутствии задачи, а руководитель получает отчёт
- **AND** отчёт содержит общую причину и данные профиля стажёра

#### Scenario: Ошибка модели или записи

- **WHEN** модель возвращает неподходящий ID или запись в Jira завершается ошибкой
- **THEN** интерфейс предлагает повторить запрос, а назначение и отчёт не создаются

### Requirement: Отчёт руководителю

Назначение, ответ стажёру и отчёт руководителю SHALL сохраняться одной транзакцией. Отчёт адресуется руководителю из профиля стажёра и содержит ФИО, роль, грейд, команду и результат.

#### Scenario: Повтор подбора

- **WHEN** стажёр повторяет запрос после назначения или сообщения об отсутствии задач
- **THEN** бэкенд сохраняет максимум одно назначение и одно уведомление на каждый исход для этого стажёра

### Requirement: Переписка о задаче

Система SHALL сохранять историю личного чата и давать модели контекст текущей задачи и до восьми пар реплик.

#### Scenario: Уточнение и сброс

- **WHEN** стажёр спрашивает о назначенной задаче
- **THEN** бот отвечает по её контексту и истории
- **AND** после сброса следующий вопрос обрабатывается с текущей задачей и пустой историей

#### Scenario: Стажёр повторяет демо подбора

- **WHEN** стажёр нажимает «Начать подбор заново»
- **THEN** система очищает переписку, снимает его тестовое назначение и удаляет его отчёты о подборе
- **AND** при следующем запросе на подбор задача выбирается заново, а руководитель получает свежий отчёт

#### Scenario: Руководитель очищает чат с отчётами

- **WHEN** руководитель нажимает «Сбросить чат»
- **THEN** полученные им отчёты исчезают из переписки и счётчика, в том числе после перезагрузки
- **AND** новые отчёты продолжают поступать, а повторы запроса стажёра не создают дубликаты
