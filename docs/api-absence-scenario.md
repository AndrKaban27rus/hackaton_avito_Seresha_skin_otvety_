# Контракт: учебный отгул

Первый сквозной сценарий. Стажёр пишет «Мне нужен учебный отгул 20 ноября 2030 года с 14:00 до 18:00», видит черновик с датой и временем, нажимает «Отправить заявку» и получает «Заявка №12. Ожидает согласования». После обновления страницы номер и статус остаются.

Пути взяты из BACKEND.md. Сейчас бэкенд в репозитории отвечает на `/api/v1/...`, их нужно перевести на эти пути или сообщить фронту, какие оставить. Фронт обращается к `/api` на своём адресе, nginx проксирует запросы на `api:8080`.

Все поля в `snake_case`. Даты в формате `YYYY-MM-DD`, время в формате `HH:MM` в часовом поясе демо.

## 1. Сообщение в чат

`POST /api/chat`

```json
{ "message": "Мне нужен учебный отгул 20 ноября 2030 года с 14:00 до 18:00" }
```

Ответ `200`:

```json
{
  "reply": "Подготовил черновик. Проверьте дату и время и отправьте заявку.",
  "sources": [{ "source_id": "demo-study-absence", "title": "Тестовая инструкция: учебный отгул" }],
  "card": {
    "kind": "absence_draft",
    "data": {
      "draft_id": "drf-7f3a",
      "expires_at": "2030-11-11T10:25:00Z",
      "date": "2030-11-20",
      "start_time": "14:00",
      "end_time": "18:00"
    }
  }
}
```

- Если черновика нет, `card` равно `null`.
- Если в сообщении не хватает данных (нет даты, конец раньше начала, дата прошла), бэкенд объясняет это в `reply` и не присылает карточку.
- `sources` может быть пустым. Фронт помечает каждый источник как тестовый материал.
- Карточку неизвестного вида фронт не роняет: показывает текст ответа и пометку вместо карточки.

## 2. Кнопка «Отправить заявку»

`POST /api/onboarding-actions/confirm`

```json
{ "draft_id": "drf-7f3a" }
```

Ответ `200`:

```json
{
  "kind": "absence_request",
  "data": {
    "request_number": 12,
    "status": "pending_approval",
    "date": "2030-11-20",
    "start_time": "14:00",
    "end_time": "18:00"
  }
}
```

- Повторный запрос с тем же `draft_id` возвращает ту же заявку с тем же номером. Фронт повторяет запрос после сетевой ошибки, поэтому это обязательно.
- `request_number` может быть числом или строкой.
- Статусы, которые знает фронт: `pending_approval` («Ожидает согласования»), `approved` («Согласована»), `rejected` («Отклонена»). Неизвестный код фронт покажет как есть.

## 3. Состояние при открытии страницы

`GET /api/state`

```json
{
  "profile": { "display_name": "Тестовый стажёр", "grade": "E1", "team": "Delivery, backend" },
  "scenarios": {
    "study_absence": {
      "request": {
        "request_number": 12,
        "status": "pending_approval",
        "date": "2030-11-20",
        "start_time": "14:00",
        "end_time": "18:00"
      }
    }
  },
  "next_step": "Дождитесь согласования учебного отгула руководителем."
}
```

- Если заявки ещё нет, `request` равно `null`.
- Остальные сценарии можно добавлять в `scenarios` по мере готовности, фронт не сломается от новых полей.
- После подтверждения фронт сам перечитывает этот запрос.

## Ошибки

Формат для всех запросов:

```json
{ "error": { "code": "draft_expired", "message": "Черновик больше не действует." } }
```

`message` пишется по-русски, его может увидеть пользователь.

| Код | HTTP | Что показывает фронт |
| --- | --- | --- |
| `draft_expired`, `draft_not_found` | 410, 404 | «Черновик больше не действует. Попросите buddy подготовить заявку заново.» Повтора нет |
| `forbidden` | 403 | «Это действие вам недоступно.» Повтора нет |
| `conflict` | 409 | Текст `message`, например о пересечении с другой заявкой. Повтора нет |
| `validation_error` | 400 | Текст `message`. Повтора нет |
| `service_unavailable` | 503 | «Сервис заявок сейчас недоступен» и кнопка повтора |
| `llm_timeout` | 504 | «Сервер долго не отвечает» и кнопка повтора |
| любой другой | 5xx | Общий текст и кнопка повтора |

Чужой и несуществующий черновик возвращают один и тот же код `draft_not_found`, чтобы по ответу нельзя было узнать о чужих черновиках.

## Таймауты на фронте

- Чат: 35 секунд. Бэкенду стоит прерывать ожидание LLM раньше, примерно через 30 секунд, и возвращать `llm_timeout`.
- Подтверждение: 15 секунд.
- Состояние: 10 секунд.

## Как проверить фронт без бэкенда

`cd frontend && npm run dev:mock`. Моки в `frontend/src/mocks/` повторяют этот контракт, на них же работают тесты.
