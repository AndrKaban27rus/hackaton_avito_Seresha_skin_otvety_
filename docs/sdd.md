# SDD: AI-buddy MVP

## Спецификация

**Пользователь:** стажёр в новой команде. **Потребность:** получить ответ по адаптации и понять следующий шаг. **Результат:** ответ с источником и актуальный чек-лист; явное действие завершения шага сохраняется.

### Functional requirements

- FR-1: показать этапы адаптации и статус каждого.
- FR-2: принять непустой вопрос разумной длины.
- FR-3: ответить по разрешённому контенту и вернуть источник.
- FR-4: при нехватке оснований предложить наставника.
- FR-5: разрешённый шаг можно завершить; повторный вызов безопасен.
- FR-6: публиковать событие завершения шага.

### Нефункциональные требования

- API версионировано; запросы валидируются сервером.
- Секреты задаются окружением; в demo нет PII.
- Простое локальное действие ориентировано на <1s; внешние вызовы имеют timeout и pending state.
- Compose поднимает стек; CI форматирует и собирает код.
- До реальных данных обязательны auth, retrieval ACL, rate limiting и transactional outbox.

### Acceptance criteria

- GIVEN demo профиль, WHEN GET onboarding, THEN API возвращает три шага.
- GIVEN вопрос об отгуле, WHEN POST chat, THEN ответ указывает тестовую инструкцию и не выдумывает порядок.
- GIVEN неизвестный вопрос, THEN система направляет к наставнику.
- GIVEN шаг чек-листа, WHEN complete, THEN статус сохраняется; повторный вызов не портит состояние.
- GIVEN недоступный assistant, THEN UI показывает ошибку и позволяет повторить запрос.

## План

1. Backend: persistence, migration/seed, endpoints, adapters, ошибки.
2. Frontend: onboarding, чат, API validation, loading/error states.
3. AI: prompt, retrieval fixture, источники, fallback examples.
4. Delivery: Compose, CI workflow, setup notes, демо.

## Решения и риски

- Один Go API и mock adapters сокращают интеграционный риск.
- LLM не меняет состояние сам; действие инициируется отдельной кнопкой.
- Риск качества модели и инструкций: ограниченный контекст, ссылки, fallback.
- Kafka событие может потеряться после commit: для MVP явно; production требует outbox.
